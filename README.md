# Kal_Beat

> 폐기된 AI 모델링 프로그램 안에서, 박자로 노이즈를 걷어내고 형태를 완성하는 1버튼 리듬 액션 게임

Kal_Beat는 모델링 과정을 음악과 전투로 시각화한 콜앤리스폰스 리듬 액션 게임입니다. 유저는 우연히 폐기된 프로그램을 실행한 `관리자`가 되고, 프로그램 안에서 오랫동안 관리자를 기다려 온 AI와 함께 비정상적인 노이즈를 제거하며 모델링 데이터를 완성합니다.

현재는 Unity와 FMOD를 연결한 전투·채보 제작 프로토타입 단계입니다.

## 프로젝트 개요

- 장르: 리듬 액션 / 캐주얼 / 3D
- 플레이 플랫폼: PC
- 출시 목표: Steam / STOVE / itch.io 등
- 엔진: Unity `6000.0.61f1`
- 언어: C#
- 오디오 및 런타임 동기화: FMOD Studio
- 현재 상태: 개발 중인 프로토타입

게임의 전투 순서는 채보가 결정합니다. 플레이어의 판정 결과는 점수, 피해 및 시각적 피드백에 영향을 주지만 전투 문장 자체를 분기시키지는 않는 것을 기본 원칙으로 합니다.

## 세계관

프로그램의 주인은 사라졌고, 내부에는 모델링 작업을 담당하던 AI만 남아 있습니다. AI는 비어 있는 가상 공간에서 자신을 다시 실행해 줄 관리자를 기다려 왔습니다. 프로그램을 발견한 유저가 관리자 권한을 인증하면서 멈춰 있던 작업대가 다시 작동하고, AI는 끝내지 못했던 모델링 작업을 재개합니다.

이 프로그램의 모델링 방식은 `비트 모델링`입니다. 디퓨전 모델이 노이즈를 제거하며 결과물을 만들어 내는 역과정에서 착안한 연산으로, 은닉층 내부의 처리 과정을 음악과 1대1 리듬 전투로 변환합니다.

- 음악은 모델링 연산이 진행되는 과정입니다.
- 노이즈 몬스터는 시스템이 스스로 제어하지 못하는 이상 파형입니다.
- 플레이어의 타이밍 입력은 연산을 보정하는 인간 개입형 정렬 데이터입니다.
- 노이즈를 끝까지 막아 내는 전투는 곧 인터랙티브 디노이징 작업입니다.
- 곡을 완주하면 노이즈가 사라지고 완성된 모델이 프로그램 내부 공간에 생성됩니다.

AI는 전문 용어를 늘어놓지만 어딘가 허술하고, 유저가 챙겨 주고 싶게 만드는 동료이자 플레이어블 캐릭터입니다. 완성된 모델이 쌓이는 빈 공간은 AI와 함께 머물고 꾸미는 허브 공간으로 확장될 예정입니다.

## 게임 루프

1. 빈 프로그램 공간의 작업대에서 정체를 알 수 없는 모델링 데이터 칩셋을 선택합니다.
2. 작업장으로 연결되는 게이트가 열리면 AI와 함께 입장합니다.
3. 음악이 끝날 때까지 노이즈 몬스터와 리듬 전투를 진행합니다.
4. 클리어하면 데이터의 정체가 공개되고 완성된 모델이 허브 공간에 생성됩니다.
5. 특정 모델링 데이터를 완성하면 조건에 따라 새로운 데이터 조각과 곡이 해금됩니다.
6. 실패하면 AI가 기절한 뒤 작업대로 돌아와 다시 도전합니다.

## 핵심 플레이

노이즈 몬스터는 먼저 준비 동작과 공격 신호를 보여 주고, AI는 타이밍에 맞춘 하나의 판정 입력으로 반격하거나 회피합니다. 조작은 단순하지만, 화면에서 벌어지는 전투는 미리 구성된 안무처럼 이어집니다.

- `Perfect`: 목표 타이밍과 매우 가깝게 입력
- `Good`: 허용 범위 안에서 입력
- `Miss`: 입력하지 않거나 허용 범위를 벗어남

전투 문법은 크게 두 가지로 나뉩니다.

- 반응형 문법: 짧은 `Ready → Timing` 신호를 보고 즉시 반응하는 근거리 중심 전투
- 패턴형 문법: 한두 마디 동안 노이즈 몬스터의 예비박을 기억한 뒤 같은 리듬으로 응답하는 원거리 중심 전투

플레이어의 원거리 공격은 독립적으로 발생하지 않고 노이즈 몬스터의 원거리 패턴 사이에 섞여 등장합니다. 공격·회피·반격의 순서는 결과에 따라 분기하지 않으며, 채보에 정해진 연극적 흐름을 유지합니다.

현재 프로토타입에는 다음 전투 유형이 구현되어 있습니다.

- 노이즈 몬스터 근거리 공격: 반격형 / 회피형
- 플레이어 근거리 대시 공격
- 노이즈 몬스터 원거리 공격: 반격형 투사체 / 회피형 빔
- 플레이어 원거리 공격
- 거리 밴드와 좌우 이동을 사용한 전투 위치 계산
- 판정 결과에 따른 이동, 피격, 색상 및 애니메이션 피드백

### 기획된 판정과 난이도

- `Perfect`: 100점
- `Good`: 50점
- `Miss`: 0점 및 HP 1 감소
- 기본 HP: 10
- `S+`: All Perfect
- `S`: Miss 없이 클리어
- `A ~ D`: 총점 비율로 산정하며 B 이상부터 클리어 및 보상 획득

난이도는 `Normal`, `Hard`, `Extreme` 세 단계를 계획하고 있습니다. Extreme은 Hard 판정 범위에 HP 1 규칙이 적용되어 한 번의 Miss로 게임 오버됩니다. 점수·HP·등급·난이도 UI는 아직 전체 게임 루프와 함께 구현할 대상입니다.

## 실행 방법

### 준비 사항

- Unity Hub
- Unity Editor `6000.0.61f1`
- FMOD Studio 프로젝트나 오디오 이벤트를 수정하려는 경우 호환되는 FMOD Studio

### 프로토타입 실행

1. Unity Hub에서 이 프로젝트 폴더를 엽니다.
2. `Assets/Scenes/PrototypeCombat.unity` 씬을 엽니다.
3. FMOD 뱅크가 최신 상태인지 확인합니다.
4. Play Mode를 시작합니다.
5. 키보드 `Space`로 판정 입력을 실행합니다.

`PrototypeCombat`은 현재 Build Settings에서 활성화된 메인 테스트 씬입니다. 재생을 시작하면 `Test_Song` 채보와 연결된 FMOD 이벤트가 자동으로 시작됩니다.

## 주요 시스템

| 시스템 | 역할 |
| --- | --- |
| `ChartData` | 곡 메타데이터, 원본 이벤트와 빌드된 전투 타임라인 보관 |
| `ChartValidator` | 저장 전 채보 메타데이터·이벤트·패턴 규칙 검증 |
| `ChartResolvedTimelineBuilder` | 전투 위치, 이동, 원거리 투사체 경로 등을 미리 계산 |
| `CombatTimelineController` | FMOD 재생 위치를 기준으로 전투 이벤트 실행 |
| `CombatJudgementSystem` | 입력 시각을 FMOD 타임라인으로 변환하고 판정 계산 |
| `CombatDuelRoot` | 전투용 로컬 좌표와 Unity 월드 좌표 변환 |
| `MonsterDefinition` | 노이즈 몬스터 프리팹, 이동 시간과 지원 패턴 정의 |
| `PatternDefinition` | 하나의 전투 문장을 구성하는 준비·타이밍 단계 정의 |

런타임 데이터 흐름은 다음과 같습니다.

```text
ChartData
  -> 패턴 동기화 및 검증
  -> 씬 기준 위치·앵커 해석
  -> ResolvedTimeline 생성
  -> FMOD 타임라인 기반 전투 실행
  -> 플레이어 입력 판정 및 피드백
```

## 채보 편집

Unity 메뉴에서 `Tools > KalBeat > Chart Editor`를 열어 채보를 편집할 수 있습니다.

기본 작업 순서는 다음과 같습니다.

1. 편집할 `ChartData`를 선택합니다.
2. BPM, 오프셋, 곡 길이와 FMOD 이벤트 경로를 설정합니다.
3. 레인에 노이즈 몬스터 정의를 연결합니다.
4. 전투 패턴을 배치하거나 이벤트를 직접 편집합니다.
5. 필요하면 FMOD 미리 듣기와 메트로놈으로 타이밍을 확인합니다.
6. 검증 결과를 확인한 뒤 저장합니다.

저장 시 연결된 패턴을 동기화하고 채보를 검증한 다음, 현재 전투 씬의 앵커를 사용해 `ResolvedTimeline`을 생성합니다. 오류가 하나라도 있으면 저장이 차단되며 경고만 있는 경우에는 저장할 수 있습니다.

주요 채보 규칙:

- 모든 이벤트의 기준 단위는 초가 아니라 `beat`입니다.
- 런타임 필수 메타데이터는 `bpm`, `offsetSec`, `fmodEventPath`입니다.
- 같은 시간 슬롯에는 최대 4개의 이벤트를 배치할 수 있습니다.
- 런타임 동기화의 기준은 `Time.time`이 아니라 FMOD 재생 타임라인입니다.
- 원거리 이벤트를 저장하려면 플레이어·노이즈 몬스터·투사체 관련 씬 앵커가 올바르게 연결되어 있어야 합니다.

## FMOD 작업 흐름

FMOD 관련 변경은 반드시 다음 순서로 반영합니다.

```text
FMOD Studio에서 Save
  -> Build Banks
  -> Unity에서 Refresh
```

- FMOD 프로젝트: `FMOD_PJ/Kal_Beat/Kal_Beat.fspro`
- 뱅크 출력 폴더: `FMOD_PJ/Kal_Beat/Build`
- 주요 뱅크: `Master`, `Song_Test`, `EditorPreview`

Unity 에디터의 미리 듣기는 제작 보조 기능이며, 실제 게임 재생과 판정의 기준은 FMOD 런타임 타임라인입니다.

## 현재 한계

이 프로젝트는 아직 완성된 게임이 아니라 전투 및 채보 제작 파이프라인을 검증하는 단계입니다.

- 현재 런타임은 하나의 활성 노이즈 몬스터 레인을 중심으로 동작합니다.
- 작업대, 데이터 칩셋 선택, 게이트, 완성 모델 생성과 허브 꾸미기는 아직 기획 단계입니다.
- AI 캐릭터와의 상호작용 및 스토리 연출은 아직 구현되지 않았습니다.
- HP, 점수 UI, 난이도, 보상과 진행도 등 전체 게임 루프는 아직 구현 대상입니다.
- 일부 씬과 에셋은 실험 또는 이전 테스트 용도로 남아 있습니다.
- `Test_Song2`의 빌드된 타임라인은 원본 이벤트 변경 후 다시 생성해야 합니다.
- 아트와 전투 피드백은 프로토타입 품질이며 계속 변경될 수 있습니다.

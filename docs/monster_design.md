# Monster Design Guide

## 목적
- 이 문서는 몬스터 기획을 코드/차트/런타임 구현으로 옮길 때 필요한 최소 정보를 정리한다.
- 새 몬스터 개발을 시작할 때는 이 문서를 먼저 참고한다.
- 기획 정보가 부족하면 이 문서를 기준으로 어떤 추가 정보가 필요한지 확인한다.

## 현재 전제
- 전투는 1대1 프로토타입 기준으로 시작한다.
- 차트의 시간 기준은 beat다.
- 런타임 동기화 기준은 FMOD timeline이다.
- 방향 기준은 기본적으로 플레이어 시점 기준이다.
- 현재 목표는 플레이 중 복잡한 계산을 최소화하고, 가능하면 전투 시작 전에 논리 상태를 시뮬레이션해 캐시하는 구조다.
- 가능하면 성공/실패가 최종 논리 상태를 다르게 만들지 않도록 설계한다.

## 용어 정리
- `PatternDefinition`은 현재 코드 자산 이름이다.
- 기획 문서에서는 원거리 `패턴형`과 헷갈리지 않도록 가능하면 아래 표현을 우선 사용한다.
  - `전투 문장`
  - `문장 템플릿`
  - `근거리 문장`
  - `원거리 문장`
- 즉 코드에서는 당분간 `PatternDefinition`을 유지해도 되지만, 기획 대화에서는 `문장 템플릿`이라고 부르는 쪽이 더 덜 헷갈린다.

## 몬스터 기획을 받을 때 필요한 정보
아래 항목이 채워지면 구현을 바로 시작하기 쉽다.

### 1. 기본 정보
- 몬스터 이름
- 내부 식별용 영문 이름 또는 `monsterId`
- 몬스터 타입
  - `Melee`
  - `Ranged`
  - `Hybrid`
- 프로토타입 표현 방식
  - 예: `Cube`
  - 예: `임시 색 변화`
- 실제 프리팹 사용 여부
  - 없으면 `없음`

### 2. 시작 상태
- 기본 시작 거리 밴드
  - 예: `4`
  - 예: `8`
- 시작 시 플레이어와 몬스터의 기본 대치 관계
  - 기본값은 `정면 대치`
- 이 몬스터가 여러 시작 밴드에서 동작 가능한지
  - 가능하면 허용 밴드 목록
  - 아니면 고정 시작 밴드

### 3. 지원 패턴 목록
패턴마다 아래 정보를 준다.

- 패턴 이름
- 패턴 영문 식별자
- `CombatKind`
  - 예: `MeleeThreatDodgeOnly`
  - 예: `MeleeThreatCounterable`
- 이 패턴의 목적
  - 예: `근거리 회피형 몸통박치기`
  - 예: `근거리 반격형 들이받기`

### 4. 패턴 step 정보
각 패턴은 step 단위로 아래 정보를 가진다.

- `BeatOffsetFromTiming`
  - 기본값: 별도 언급이 없으면 `Ready`는 `Timing 1박 전`
- `Phase`
  - `Ready`
  - `Timing`
- `ReadyCueType`
  - `Pose`
  - `Move`
  - `Timing step`이면 `None`
- step의 의미
  - 예: `웅크리기`
  - 예: `측면 이동`
  - 예: `직진 접근`

### 5. 이동 규칙
이 항목이 밴드 방식 구현의 핵심이다.

몬스터 쪽에 대해:
- `Move`가 있는지
- 있다면 어떤 이동인지
  - 같은 밴드 유지 측면 이동
  - 직진 접근
  - 뒤로 물러남
  - 잠근 목표 위치로 돌진
- 이동량
  - 예: `2`
  - 예: `4`
- 이동 방향을 누가 정하는지
  - 패턴이 고정
  - 차트가 지정
  - 현재 권장: 몬스터 `Move` 방향은 패턴이 고정

플레이어 쪽에 대해:
- 회피/피격/넉백 이동량
- 방향을 누가 정하는지
  - 현재 권장: 플레이어 회피 방향만 차트가 지정

### 6. Timing 결과 규칙
패턴 결과는 아래 항목이 명확해야 한다.

- `Timing`에서 몬스터가 어디를 목표로 하는지
  - 예: `공격 시작 순간의 플레이어 위치를 잠금`
  - 예: `현재 전투 축의 2밴드`
- 플레이어 결과 이동
  - 예: `오른쪽 4 회피`
  - 예: `피격으로 뒤로 2`
- 몬스터 결과 이동
  - 예: `추가 이동 없음`
  - 예: `넉백 4`
- 반격 시 넉백 크기
  - 플레이어 넉백 거리
  - 몬스터 넉백 거리
  - 둘이 다를 수 있으면 각각 따로 명시
- 성공/실패가 최종 논리 상태를 바꾸는지
  - 현재 권장: 가능하면 `바꾸지 않음`

### 7. 이벤트 종료 후 상태
다음 문장으로 이어지려면 아래가 필요하다.

- 이벤트 종료 후 최종 몬스터 밴드
- 이벤트 종료 후 최종 플레이어 밴드 또는 상대 위치
- 다음 패턴 시작이 가능한지
- 다음 패턴이 가능하려면 어떤 밴드로 정리되어야 하는지

## 기획을 줄 때 권장 템플릿
아래 형식으로 주면 구현이 빠르다.

설명:

step 0:
- BeatOffsetFromTiming:
- Phase:
- ReadyCueType:
- 의미:
- 이동 타입:
- 이동량:
- 이동 방향 결정 주체:

- BeatOffsetFromTiming:
- Phase:
- 의미:

- 몬스터 목표:
- 플레이어 이동:

## 정보가 부족할 때 우선 확인해야 하는 질문
아래는 구현 전에 꼭 확인해야 하는 항목이다.

### 필수
- 시작 밴드가 몇인지
- 이 패턴이 어떤 `CombatKind`인지
- `Ready`가 `Pose`인지 `Move`인지
- `Timing`에서 플레이어가 어느 방향으로 얼마나 이동하는지
- `Timing`에서 몬스터가 어디로 가는지
- 반격형이면 플레이어와 몬스터가 각각 얼마나 넉백되는지
- 이벤트 종료 후 다음 패턴이 가능한 최종 상태가 무엇인지

### 있으면 좋은 정보
- 프로토타입 연출 방식
- 색 변화 / 스케일 변화 / 임시 애니메이션 여부
- 성공/실패 시 시각 연출 차이

## `PatternStepDefinition`의 현재 필드
현재 구현된 필드는 아래와 같다.

- `BeatOffsetFromTiming`
- `Phase`
- `ReadyCueType`
- `DirectionHint`

이 상태만으로는 `Move`를 제대로 밴드 방식으로 해석하기 어렵다.

## `PatternStepDefinition`에 앞으로 필요한 이동 필드
아래 필드는 밴드 방식으로 확장할 때 권장되는 후보들이다.

### 1. `MovementResolveMode`
이 step이 어떤 방식으로 목표 위치를 계산하는지 정의한다.

예시 값:
- `None`
- `LockedApproach`
- `ForwardToBand`
- `SideMoveOnBand`
- `Knockback`
- `RetreatToBand`

### 2. `MoveUnits`
이 step에서 이동하는 논리 거리다.

예:
- `2`
- `4`
- `8`

### 3. `TargetBandUnits`
이 step이 끝난 뒤 목표로 하는 밴드다.

예:
- 같은 밴드 유지 측면 이동
- `4 -> 2` 접근
- `0 -> 4` 넉백 복귀

### 4. `MovementDirectionHint`
몬스터 `Move`가 좌/우 해가 필요한 경우 어떤 쪽을 택할지 정한다.

중요:
- 이 값은 현재 `DirectionHint`와 역할이 다르다.
- 현재 권장 방향은:
  - 플레이어 회피 방향은 차트가 가짐
  - 몬스터 `Move` 방향은 패턴 step이 가짐

즉 나중에는 `DirectionHint`를 두 역할로 나누는 것이 좋다.

### 5. `LockPlayerPositionOnStepStart`
이 step 시작 시 플레이어 위치를 잠글지 여부다.

예:
- `Timing`의 접근 돌진은 `true`
- 일반 준비 이동은 `false`

### 6. `InterruptCurrentMotionOnEnter`
이 step이 시작될 때 이전 이동을 끊고 새 목표로 전환할지 여부다.

이 값이 필요한 이유:
- 반격형에서 입력이 약간 빠르거나 늦어도
- `Timing`에 도달하면 `approach` 중간이라도
- 즉시 `post-result target`으로 재타깃해야 하기 때문이다.

## 밴드 방식에서 권장되는 추가 데이터
`PatternStepDefinition`만으로 부족한 정보는 패턴/몬스터 단위로도 필요할 수 있다.

### `PatternDefinition` 쪽에 두기 좋은 것
- `entryBandUnits`
- `expectedExitBandUnits`
- 이 패턴이 허용하는 시작 밴드 목록
- 플레이어 방향 선택이 필요한지 여부

### `MonsterDefinition` 쪽에 두기 좋은 것
- 이 몬스터가 지원하는 `MovementResolveMode` 목록
- 기본 접근 거리
- 기본 복귀 거리
- 밴드 방식 지원 여부

## 구현 방향 권장안
1. 패턴은 가능한 값만 가진다.
2. 차트는 가능한 한 `플레이어 쪽 선택 정보`만 가진다.
3. 몬스터 이동은 패턴 step 정의가 가진다.
4. 전투 시작 전에 차트를 한 번 시뮬레이션해 `ResolvedChartEvent` 캐시를 만든다.
5. 플레이 중에는 캐시를 재생만 한다.

## 현재 기준의 간단한 해석 규칙
- `Ready + Pose`
  - 위치 변화 없음
- `Ready + Move`
  - 패턴 step의 이동 규칙을 따른다
- `Timing`
  - 몬스터는 잠근 목표 또는 패턴이 정한 목표로 간다
  - 플레이어는 차트가 정한 방향으로 결과 이동한다

## 정리
몬스터 기획에서 가장 중요한 건 아래 네 가지다.

1. 시작 밴드
2. step별 이동 규칙
3. `Timing` 결과 이동 규칙
4. 이벤트 종료 후 다음 패턴으로 이어지는 최종 상태

이 네 가지가 명확하면 구현과 검증이 훨씬 쉬워진다.

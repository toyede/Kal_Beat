# Kal_Beat Game Design

> 기획 기준: [칼박 요약 기획서](https://app.notion.com/p/39ba0b77359f809fa46ecd4b70a0bb64)

## 1. 프로젝트 정의

- 플레이 플랫폼: PC
- 출시 목표: Steam, STOVE, itch.io 등
- 장르: 콜 앤 리스폰스 기반 리듬게임, 액션, 캐주얼, 3D
- 개발 엔진: Unity 6, FMOD
- 현재 단계: 전투 및 채보 제작 프로토타입
- 핵심 방향: 폐기된 AI 모델링 프로그램 안에서 박자에 맞춰 노이즈를 제거하고 모델링 데이터를 완성하는 리듬 액션 게임

Kal_Beat는 복잡한 콤보나 실시간 스킬 선택보다 음악과 예비 동작을 읽고 정확한 타이밍에 반응하는 감각을 중심으로 설계한다. 전투는 모델링 연산을 시각화한 장면이며, 유저의 입력은 AI가 혼자 처리하지 못하는 노이즈를 정렬하는 데이터로 사용된다.

---

## 2. 세계관과 주요 역할

### 2-1. 프로그램

- 과거 모델링 작업을 위해 제작되었으나 세상 밖으로 나오지 못한 채 폐기된 프로그램이다.
- 프로그램 내부에는 아무것도 없는 가상 공간과 모델링 작업대가 남아 있다.
- 작업대는 관리자 권한이 있어야 실행할 수 있다.
- 모델링 결과는 프로그램 내부에서는 완벽하게 구현되지만 외부로 내보내는 기능이 없다.

### 2-2. 유저: 관리자

- 유저는 폐기된 프로그램을 우연히 발견해 실행한 외부의 관리자다.
- 유저의 관리자 권한 인증으로 멈춰 있던 작업대가 다시 작동한다.
- 실제 조작과 타이밍 입력을 제공하며 AI의 모델링 연산에 개입한다.
- 세계 안에서는 직접 싸우는 인물보다 AI에게 판단 데이터를 제공하는 협력자에 가깝다.

### 2-3. 플레이어블 캐릭터: 모델링 AI

- 프로그램 내부에서 오랫동안 관리자를 기다려 온 모델링 AI다.
- 리듬 전투에서 화면에 보이고 움직이며 공격·회피·피격하는 주체다.
- 전문 용어를 장황하게 설명하지만 어딘가 허술하고, 유저가 챙겨 주고 싶게 만드는 캐릭터를 지향한다.
- 모델링을 다시 할 수 있게 된 사실과 완성품을 만들어 냈다는 사실에 강한 기쁨을 보인다.

### 2-4. 노이즈 몬스터

- AI가 은닉층 내부에서 스스로 제어하지 못하는 이상 파형을 전투 가능한 형태로 시각화한 존재다.
- 게임 시스템상으로는 공격 신호와 리듬 문장을 제공하는 1대1 전투 상대다.
- 세계관상으로는 제거해야 할 악당이라기보다 모델링 완료를 방해하는 불안정한 연산 상태다.
- 곡이 끝날 때까지 노이즈를 억제하면 디노이징이 완료되고 노이즈 몬스터는 사라진다.

---

## 3. 비트 모델링

비트 모델링은 디퓨전 모델의 역프로세스를 응용했다는 설정의 독자적인 모델링 방식이다.

1. 프로그램이 은닉층에 무작위 잠재 노이즈를 만든다.
2. 모델링 연산이 음악과 작업장 공간으로 시청각화된다.
3. 이상 파형은 노이즈 몬스터와 공격 패턴으로 나타난다.
4. 유저가 박자에 맞춘 타이밍 데이터를 제공한다.
5. AI는 입력을 인간 개입형 정렬 데이터로 사용해 노이즈를 억제한다.
6. 곡을 완주하면 인터랙티브 디노이징이 끝나고 최종 모델이 완성된다.

AI의 긴 설명을 플레이어에게 전달할 때는 다음 한 문장으로 축약한다.

> 은닉층의 연산을 음악과 노이즈 몬스터로 시각화한 공간에서 박자에 맞춰 싸우며 모델링을 완성한다.

---

## 4. 핵심 경험

### 4-1. 플레이 경험

- 하나의 핵심 판정 입력으로 복잡해 보이는 전투 안무를 수행한다.
- 즉흥적인 기술 선택보다 차트에 정의된 흐름을 정확하게 연기하는 감각을 우선한다.
- 노이즈 몬스터의 예비 동작과 리듬을 읽고 AI를 도와준다는 협력감을 만든다.
- 곡을 클리어할 때까지는 무엇을 모델링하는지 알 수 없고, 완성 순간에 결과물이 드러나는 기대감을 만든다.
- 완성 모델이 허브 공간에 쌓이며 진행 과정이 시각적으로 남는다.
- AI와 상호작용하고 빈 공간을 꾸미며 캐릭터를 돌보는 애착 경험을 제공한다.

### 4-2. 감정과 분위기

- 핵심 감정은 버려진 AI와 새로운 관리자가 함께 쓸모를 증명해 나가는 관계다.
- AI는 귀엽고 허술하지만 모델링 작업에는 진심인 인물로 표현한다.
- 가상공간의 공허함과 음악·전투가 시작될 때의 활기를 대비시킨다.
- 결과물을 외부로 내보낼 수 없다는 결함은 웃음과 애착, 프로그램의 존재 가치에 대한 갈등을 동시에 만든다.

## 5. 게임 루프

### 5-1. 최초 진입

1. 유저가 폐기된 프로그램을 실행한다.
2. 프로그램 내부의 AI와 만난다.
3. 작업대 접근 시 관리자 권한을 확인한다.
4. 권한 인증에 성공하면서 AI가 작업대를 다시 사용할 수 있게 된다.
5. 싱크 조절과 기본 조작을 익히는 첫 비트 모델링을 진행한다.

### 5-2. 반복 플레이 루프

1. 허브의 작업대에서 `???`로 표시된 모델링 데이터 칩셋을 선택한다.
2. 작업장으로 연결되는 게이트가 열리면 AI가 입장한다.
3. 음악이 끝날 때까지 노이즈 몬스터와 1대1 리듬 전투를 진행한다.
4. 클리어하면 데이터의 제목과 모델링 주제가 공개된다.
5. 허브 천장에 열린 통로에서 완성된 모델이 떨어지며 공간에 남는다.
6. 클리어 조건을 검사해 새로운 데이터 조각 또는 칩셋을 해금한다.
7. 허브에서 AI와 상호작용하거나 완성 모델을 확인한 뒤 다음 작업을 선택한다.

### 5-3. 실패

- HP가 모두 소진되면 해당 모델링 작업에 실패한다.
- AI가 기절한 뒤 작업대로 돌아오는 연출을 사용한다.
- 선택한 데이터는 사라지지 않으며 같은 작업에 다시 도전할 수 있다.
- 실패는 진행 경로를 영구적으로 막지 않는다.

### 5-4. 모델링 데이터와 해금

- 미완료 데이터 칩셋은 제목과 디자인을 감추고 `???`와 회색 계열로 표시한다.
- 클리어하면 곡 제목, 모델링 주제와 디자인이 드러난다.
- 특정 데이터들을 이미 완성했는지 조건을 확인해 추가 데이터 조각을 지급한다.
- 데이터 조각은 새로운 곡과 모델링 작업을 여는 진행 자원이다.
- 완성 모델은 단순 보상 아이콘이 아니라 허브를 채우고 꾸미는 실제 오브젝트로 활용한다.

## 6. 리듬 전투

### 6-1. 기본 원칙

- 액션 게임 위에 리듬을 얹는 것이 아니라 리듬게임 위에 전투 연출을 얹는 구조다.
- 플레이어가 어떤 기술을 사용할지는 차트가 결정한다.
- 유저는 그 행동을 얼마나 정확한 타이밍에 수행했는지에 집중한다.
- 공격·회피·반격 순서는 판정 결과로 분기하지 않는다.
- 성공과 실패는 점수, HP, 피드백에 영향을 주지만 다음 전투 문장의 논리 상태는 가능하면 동일하게 유지한다.
- 런타임 전투 시간은 FMOD timeline을 기준으로 한다.

### 6-2. 반응형 문법

- 근거리 전투의 기본 문법이다.
- 짧은 Ready 신호와 예비 동작을 보고 Timing에 즉시 반응한다.
- 짧고 강한 한 박 중심의 전투 감각을 만든다.

예시:

- `ready(pose) -> timing`
- `ready(move) -> ready(move) -> timing`
- 플레이어 근거리 공격의 `ready -> timing`
- 플레이어 근거리 연속 문장의 `ready -> ready -> timing -> timing`

### 6-3. 패턴형 문법

- 원거리 전투의 기본 문법이다.
- 한 마디 또는 두 마디 동안 노이즈 몬스터가 제시한 예비박을 기억하고 뒤이어 같은 리듬으로 응답한다.
- 반복, 쉼표와 묶음이 있는 리듬 문장을 읽는 감각을 우선한다.
- 플레이어 원거리 공격은 독립적으로 발생하지 않고 노이즈 몬스터의 원거리 문장 사이에 섞여 등장한다.

### 6-4. 노이즈 몬스터 공격

#### 근거리 회피형

- 노이즈 몬스터의 공격을 AI가 좌우로 회피한다.
- 반응형 문법을 사용한다.
- 차트가 플레이어 회피 방향을 지정한다.

#### 근거리 반격형

- AI가 타이밍에 맞춰 공격을 받아치거나 패링한다.
- 반응형 문법을 사용한다.
- 반격 후 플레이어와 노이즈 몬스터의 넉백 위치를 미리 계산한다.

#### 원거리 회피형

- 노이즈 몬스터가 제시한 리듬에 맞춰 투사체나 빔을 회피한다.
- 패턴형 문법을 사용한다.

#### 원거리 반격형

- 노이즈 몬스터의 원거리 공격을 정해진 응답 타이밍에 반격한다.
- 패턴형 문법을 사용한다.
- 투사체의 생성, 이동과 접촉 시각을 차트 저장 시 미리 계산한다.

### 6-5. 플레이어 공격

#### 플레이어 근거리 공격

- 반응형 문법 기반 공격이다.
- Ready 단계에서 공격 마크가 등장한다.
- Timing 전에 접근하고 타이밍에 맞춰 돌진 또는 타격한다.

#### 플레이어 원거리 공격

- 패턴형 문법 기반 공격이다.
- 노이즈 몬스터의 원거리 공격 흐름 안에 응답의 일부로 배치된다.
- Perfect 또는 Good 판정에서 투사체를 발사하고 Miss에서는 발사하지 않는다.

## 7. 판정, 결과와 난이도

### 7-1. 판정과 HP

- Perfect: 100점
- Good: 50점
- Miss: 0점, HP 1 감소
- 기본 HP: 10
- HP가 모두 소진되면 게임 오버

### 7-2. 결과 등급

- All Perfect 달성 시 S+
- Miss 없이 클리어 시 S
- 그 외에는 총점 비율에 따라 A ~ D 등급
- B 이상을 받아야 클리어로 판정하고 보상을 획득

### 7-3. 난이도

- Normal: 기본 판정 범위를 사용하는 표준 난이도
- Hard: 더 좁은 판정 범위
- Extreme: Hard 판정 범위, HP 1, 한 번의 Miss로 게임 오버

현재 프로토타입에는 타이밍 판정 자체가 구현되어 있다. HP, 점수 합산, 결과 등급, 난이도 선택과 보상 지급은 향후 전체 게임 루프에 연결한다.

## 8. 스토리 진행

### 8-1. 시작

- 폐기된 프로그램을 유저가 실행한다.
- AI는 오랫동안 기다린 관리자가 왔다고 생각하고 반가워한다.
- 관리자 인증을 통해 멈춰 있던 작업대를 가동한다.
- 첫 모델링 작업을 튜토리얼로 사용해 비트 모델링과 타이밍 입력을 설명한다.

### 8-2. 중반 진행

- 모델링을 반복할수록 빈 허브 공간에 완성 모델이 늘어난다.
- 새로운 데이터 조각과 작업이 열리며 AI의 기능과 과거를 조금씩 드러낸다.
- AI와 유저의 관계는 단순한 프로그램과 관리자를 넘어 서로의 존재 가치를 인정하는 방향으로 발전한다.

### 8-3. 핵심 갈등

- 유저가 완성 모델을 실제로 사용하려 할 때 프로그램에 내보내기 기능이 없다는 사실이 드러난다.
- AI는 내부에서는 완벽한 모델을 만들 수 있지만 결과물을 외부로 전달할 수 없다.
- 자신이 다시 폐기될 것을 두려워한 AI는 유저에게 프로그램을 버리지 말아 달라고 매달린다.
- 이 결함을 언제 공개할지와 이후 결말은 아직 확정하지 않는다.

## 9. 비주얼, 오디오와 카메라

### 9-1. 비주얼 방향

- 핵심 키워드는 AI, 가상공간, 음악, 은닉층과 노이즈다.
- 허브는 처음에는 비어 있고 정적인 공간이지만 완성 모델이 쌓이며 점차 생활감과 색을 얻는다.
- 작업장은 모델 내부 연산을 시각화한 비현실적인 전투 공간이다.
- 노이즈 몬스터는 각 모델링 데이터의 이상 파형과 음악적 성격이 읽히는 실루엣을 가져야 한다.
- 전투 동작은 과장된 키포즈와 명확한 방향성으로 타이밍 가독성을 우선한다.
- 카툰 렌더링을 기반으로 캐릭터와 공격 신호를 명확하게 구분하는 방향을 검토한다.

### 9-2. 오디오 방향

- 음악은 BGM이면서 모델링 연산 그 자체다.
- 플레이어가 박자, 준비 신호, 공격음과 판정 피드백을 먼저 인식할 수 있어야 한다.
- 노이즈 몬스터의 리듬 문장과 시각 동작이 같은 음악적 특징을 공유해야 한다.
- 전투 재생과 판정의 시간 기준은 FMOD timeline이다.
- 에디터 미리 듣기는 제작 보조 기능이며 런타임의 시간 권위가 아니다.

### 9-3. 카메라 방향

- 현재 프로토타입은 쿼터뷰 카메라를 기본으로 사용한다.
- AI와 노이즈 몬스터, 공격 방향과 Ready 신호가 동시에 읽히는 구도를 우선한다.
- 이동 중에는 시야를 유지하고 이동 종료 후 필요할 때 회전한다.
- 향후 작업장 회전과 카메라 무빙을 추가하더라도 판정 가독성과 멀미 방지를 우선한다.

## 10. 제작 도구와 데이터 원칙

### 10-1. 차트 데이터

- `ChartData`를 기준 저장 포맷으로 사용한다.
- 이벤트의 기준 시간 단위는 beat다.
- 런타임 필수 메타는 `bpm`, `offsetSec`, `songLengthSec`, `fmodEventPath`다.
- JSON은 보조 입력 소스로 사용하고 최종 편집과 저장은 ChartData 기준으로 유지한다.
- 한 타임 슬롯에는 최대 4개의 이벤트를 허용한다.

### 10-2. 저장과 검증

- 연결된 문장 템플릿을 동기화한다.
- BPM, 곡 길이, 그리드, 필수 메타와 이벤트 구조를 검증한다.
- Error가 하나라도 있으면 저장을 차단하고 Warning만 있으면 허용한다.
- 현재 전투 씬의 앵커를 해석해 런타임용 `ResolvedTimeline`을 생성한다.
- 차트나 몬스터 정의가 변경되어 signature가 일치하지 않으면 오래된 타임라인 재생을 막는다.

### 10-3. 런타임 재생

- 런타임 동기화 기준은 FMOD timeline이다.
- raw 이벤트를 플레이 중 즉석 해석하지 않고 저장 시 미리 계산한 전투 데이터를 재생한다.
- 플레이어와 노이즈 몬스터의 위치는 duel-local 좌표와 거리 band를 사용해 계산한다.
- 기본 FMOD 작업 흐름은 `Save -> Build Banks -> Unity Refresh`다.
